# KITCHEN STOCK
飲食店向け在庫・発注管理のブラウザ保存型MVP。

## 起動
このフォルダで `npm install`、`npm run dev` を実行し http://127.0.0.1:4173 を開く。
開発サーバーには Python 3 を使用します。
依存パッケージ・ビルド工程は不要。`node --check dist/app.js` で構文確認。

## 機能
- 食材登録・編集、仕入先・単価・発注点設定
- 検索、カテゴリ・要発注フィルタ
- 入庫、出庫、廃棄、棚卸と履歴
- 適正数未満の商品から仕入先別に発注作成（適正数−現在庫−未入荷数量）。旧登録商品は従来の発注点方式を維持。
- 一括入荷と在庫加算、二重入荷防止
- 在庫CSV、発注CSV、JSONバックアップ出力

## 初期版の範囲
発注表から転記した101品目（9分類）から開始。在庫・単価は未入力であり、写真の手書き在庫を現在値として取り込みません。データは同一ブラウザ・同一オリジンのlocalStorageに保存。
複数端末・スタッフ間の同期、発注先への送信、分納・発注取消、期限・ロット管理、バックアップ復元は未実装。
ブラウザのサイトデータ削除で記録が消えるため、必要な記録はバックアップを保存する。
発注の「発注済み」はアプリ内の管理状態であり、仕入先への送信完了を意味しない。
本運用向けには共有DB・認証権限・復元・並行更新対応を追加する。

## Vercel＋Supabase移行

共有同期版のデータベース定義は `supabase/schema.sql` にあります。Supabase SQL Editorでこのファイル全体を実行し、Vercelに `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` をProduction・Preview・Developmentへ設定してください。`vercel.json` が `npm run build` と `dist` 出力を指定するため、GitHubへのpush後に自動デプロイされます。

初回はSupabase Authでスタッフ用アカウントを作成し、SQL Editorで店舗とメンバーを登録します。`store_state` に店舗ごとの在庫・発注データを保存し、同じ店舗のログインユーザーへRealtimeで反映します。Supabaseのメール確認を有効にしている場合は、確認メールのリンクを開いてからログインしてください。

複数店舗を使う場合は `stores` に店舗を追加し、同じユーザーを各店舗の `store_members` に登録します。ログイン後、画面左側の店舗セレクターから切り替えられます。店舗ごとに在庫・発注・履歴は分離されます。

ブラウザで不足5食材→仕入先4社への発注分割、トマト8kg入荷（2→10kg）、再読込後の永続化を確認。

## 発注項目（2026-10-22）
客席備品9、テイクアウト用品9、トイレ用品8、洗剤5、食材8、ドリンク17、冷凍食材2、調味料23、消耗品20、計101品目。
ニトリル手袋はM・Lを別商品に分割。ミニ雪見だいふく（白）はユーザー確認済みの適正数6箱。カップ専用蓋はユーザー指定の名称。
`dist/catalog.js` に商品名・仕入先・適正数を収録。判読不確実な表記・規格には確認メモを付けています。
原票に明記のない単位は商品形態からの初期値です。実際の仕入単位に合わせて編集してください。
画像、手書きの在庫数、連絡先はリポジトリに含めていません。

旧サンプル10品目は「旧登録項目」に移動し、在庫・発注・履歴は保持します。独自に追加した商品も維持します。
移行前データは同じブラウザの `kitchen-stock-v1-before-catalog` に保管します。移行は一度のみ行い、再読込で数量を初期化しません。
在庫未入力の商品は自動発注候補に含めず、入荷・出庫の前に棚卸が必要です。単価未入力の金額は「未確定」と表示します。

検証: `npm run check`、`npm test`。テストはカタログ件数、移行の冪等性、既存履歴保持、6箱への補充、二重入荷防止、未入力在庫の扱いを確認します。
